# PostgreSQL — налаштування

## Що зберігається в БД

| Таблиця        | Що містить                                                  |
|----------------|--------------------------------------------------------------|
| `players`      | uuid → ім'я, фото профілю (переживає рестарт сервера)         |
| `packs`        | бібліотека паків вікторин (замість файлів у `public/packs`)   |
| `game_results` | історія завершених ігор: кімната, пак, переможець, рахунок    |

Активний стан гри (хто зараз ходить, поточне питання, підключені сокети) **лишається в пам'яті** — це швидкоплинні дані одного запущеного процесу, їм не місце в БД.

## 1. Встановити залежність

```bash
npm install pg
```

## 2. Підняти PostgreSQL

Локально через Docker (є готовий `docker-compose.yml`):

```bash
docker compose up -d
```

Або використайте будь-яку існуючу БД (Render, Railway, Supabase, власний сервер тощо).

## 3. Налаштувати підключення

Скопіюйте `.env.example` → `.env` і впишіть реальні дані:

```
DATABASE_URL=postgres://quiz_user:quiz_password@localhost:5432/quiz
PGSSL=false
```

Щоб `.env` підхоплювався автоматично, встановіть `dotenv` (`db.js` вже намагається його завантажити сам — просто додайте пакет):

```bash
npm install dotenv
```

Якщо `dotenv` не встановлений, `db.js` при старті одразу покаже зрозумілу підказку замість криптичної помилки `SASL: client password must be a string` — і запуск зупиниться, поки ви не пропишете змінні оточення. Без `dotenv` можна передати їх вручну перед командою:

```bash
DATABASE_URL=postgres://quiz_user:quiz_password@localhost:5432/quiz node migratePacks.js
```

## 4. Перенести існуючі паки з файлової системи (одноразово)

Якщо у вас вже є файли в `public/packs/*.json`:

```bash
node migratePacks.js
```

Скрипт безпечно запускати повторно — існуючі паки просто оновляться.

## 5. Запуск

```bash
node backend.js
```

Схема таблиць створюється автоматично при старті (`CREATE TABLE IF NOT EXISTS`) — окремих міграцій запускати не потрібно.

## Що змінилось у поведінці

- **Профіль гравця** (ім'я, фото) тепер зберігається по `uuid` в БД — якщо сервер перезапуститься, гравець з тим самим `uuid` у localStorage побачить своє ім'я й фото знову, а не скинуті на замовчування.
- **Завантажений через "Host" пак** автоматично зберігається в бібліотеку `packs` (за назвою, взятою з самого файлу) — наступного разу його можна буде обрати зі списку готових паків, не завантажуючи файл повторно.
- **Список паків у меню "Host"** тепер приходить з БД, а не зі сканування папки `public/packs`.
- **По завершенню гри** (природньому чи через "Skip round" в останньому раунді) в `game_results` записується переможець і рахунок. Це не показується в інтерфейсі — просто накопичується для майбутньої статистики/лідерборду, якщо захочете його додати.

## Якщо БД недоступна

- При старті сервер **не піднімається**, якщо не вдалось підключитись до БД (5 спроб з паузою 2с, потім явна помилка в консолі) — так простіше одразу побачити проблему з конфігурацією, ніж отримати мовчазні збої посеред гри.
- Під час роботи: якщо окремий запит до БД не вдався (наприклад, збереження імені профілю), гра **не ламається** — помилка просто логується в консоль, а функціонал, що не залежить від БД, працює далі.
